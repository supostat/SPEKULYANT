# Контент и экраны «Спекулянта» — руководство автора

Документ для тех, кто пишет данные игры и рисует экраны. Источник решений — `docs/SPEKULYANT.md`,
эталон интерфейса — `design/design-book.html`.

## Формат данных

Решение 15.7: контент пишется в TOML, один файл на сущность, в любом текстовом редакторе. Имя
файла без `.toml` — идентификатор сущности: латиница в нижнем регистре, цифры и `_`, с буквы
(`chewing_gum.toml` → `chewing_gum`). На него ссылаются другие файлы.

### Раскладка `data/`

| Путь | Что лежит |
|---|---|
| `epochs/time.toml` | календарь эпох и часы игры (решение 15.3) |
| `epochs/<эпоха>.toml` | описание эпохи, её угроза и темп дрейфа репутации; у каждой эпохи календаря оно обязательно |
| `goods/<товар>.toml` | товар и его кривая цены |
| `cities/<город>.toml` | город, толкучка, множители цен, доступность |
| `routes.toml` | направления поездок |
| `economy/market.toml` | правила толкучки: разница цен, восстановление запаса, колебания |
| `economy/money.toml` | индекс цен, деноминация, курсы чеков и доллара |
| `money/<место>.toml` | место хранения денег: валюта, окно, процент, риск |
| `reputation.toml` | пределы репутации и долгов связей |
| `factions/<фракция>.toml` | фракция репутации (решение 15.6) |
| `event_rules.toml` | шанс события в спокойный день и отдых повторяемых событий |
| `biographies/<биография>.toml` | стартовая биография |
| `npc/<человек>.toml` | шаблон соперника или знакомого |
| `events/<эпоха>/<событие>.toml` | событие эпохи |
| `zone/events/<событие>.toml` | событие зоны |

Файл вне этой раскладки — ошибка: опечатка в имени каталога не пропадёт молча.

### Деньги и даты

Цены и суммы в данных — рубли 1984 года числом (`price = 160`, `price = 4.5`): реальная стоимость.
Ядро хранит их в копейках и само переводит в номинал дня; гиперинфляция и деноминация в товарах,
биографиях и событиях не пишутся. Единственное место номинала — `economy/money.toml`: там индекс
цен и курсы в рублях на ценнике по годам. Даты — `"ГГГГ-ММ-ДД"`, не раньше `"1984-01-01"`.

Деньги игрока лежат в своей валюте: наличные и вклады в рублях обесцениваются вместе с индексом,
чеки и доллары идут по курсу дня. Поэтому гиперинфляция бьёт ровно по тем, кто держит рубли
(§5.1).

### Товар, город, маршрут, биография, человек, эпоха

```toml
# goods/jeans.toml
name = "Джинсы (фирма)"
short_name = "Джинсы"         # для окна «Карман»
category = "clothes"          # по категории город задаёт множитель
unit = "шт"
stock = 6                     # обычный запас на толкучке города
curve = [                     # цена в начале года; годы строго возрастают, до первой точки товара нет
  { year = 1984, price = 180 },
  { year = 1992, price = 60 },
]

# cities/warsaw.toml
name = "Варшава"
region = "abroad"
market = "Стадион Десятилетия"  # заголовок окна толкучки
multipliers = { clothes = 0.7 } # категория должна быть хотя бы у одного товара; без множителя — по кривой
opens = "1990-06-01"            # до этой даты город закрыт
connections_only_until = "1991-01-01"  # до этой даты — только по блату

# routes.toml
[[routes]]
from = "moscow"
to = "warsaw"
days = 2
fare = 40

# biographies/student.toml
title = "Студент"
description = "Общежитие, иностранцы-сокурсники, мало денег."
start_city = "moscow"
start_cash = 150              # наличные на старте, рубли 1984 года
contacts = ["kofi"]           # знакомые на старте — связи
starts_unlocked = true

# money/savings_bank.toml
title = "Сберкасса"
currency = "ruble"            # ruble, checks или dollar
closes = "1992-01-01"         # с этой даты туда не положить; opens — с какой можно
risk = "Заморозка вкладов"    # строка для экрана денег
interest = [{ year = 1984, percent = 2 }]  # годовой процент с начала года, начисляется первого числа
# illegal_until = "1991-01-01" — до этой даты хранение — статья (доллары)

# npc/vodka_man.toml
name = "Мужик в спецовке"
role = "случайный продавец"
faction = "people"            # участковый — militia, фарцовщик — traders
strategy = "drifter"          # только у соперника, который торгует
description = "Торгует тем, что осталось со свадьбы. Помнит обиды."

# epochs/stagnation.toml
summary = "Торговля с выгодой — спекуляция по статье 154."
threat = { faction = "militia", label = "ОБХСС" }  # чью неприязнь показывает «Карман»
reputation_drift_days = 180   # раз в столько дней репутация сдвигается на уровень к нулю

# factions/siloviki.toml
title = "Силовики"
from_epoch = "stabilization"  # без него фракция есть с начала игры

# reputation.toml
limit = 7                     # уровни репутации и отношения — от −7 до +7
max_debt = 3                  # больше стольких невозвращённых услуг человек не помогает

# event_rules.toml
daily_chance = 0.15           # вероятность, что в спокойный день что-то случится
cooldown_days = 90            # отдых повторяемого события, если у него нет своего cooldown_days
```

Фракций шесть (решение 15.6): `bandits`, `militia`, `officials`, `traders`, `people`, `siloviki`.
На них ссылаются условия и последствия событий (`reputation = [{ faction, … }]`), люди и угрозы
эпох; неизвестная фракция — ошибка валидатора, как и граница условия за пределом `limit`.

### Толкучка, индекс и курсы

```toml
# economy/market.toml — доли от средней цены или от обычного запаса товара
spread = 0.08       # разница цен покупки и продажи
recovery = 0.15     # доля отклонения запаса от обычного, которую рынок выбирает за день
daily_noise = 0.1   # случайное колебание запаса за день, по сиду мира

# economy/money.toml — рубли на ценнике в начале года; после деноминации — новые рубли
denomination = { date = "1998-01-01", factor = 1000 }
inflation = [                 # рублей на ценнике за рубль 1984 года; 1984 год — единица
  { year = 1984, rubles = 1 },
  { year = 1997, rubles = 11000 },
  { year = 1998, rubles = 20 },
]
checks_rate = [{ year = 1984, rubles = 2 }]   # рублей за чек ВПТ
dollar_rate = [{ year = 1984, rubles = 3 }]   # рублей за доллар
```

Между опорными точками кривые товаров, индекс и курсы меняются в одно и то же число раз за
день. Цена штуки на толкучке — кривая товара, множитель города, шоки событий и запас: пустой рынок
продаёт вдвое дороже, заваленный — дешевле в разы; каждая следующая штука в одной сделке дороже
при покупке и дешевле при продаже.

### Событие

Событие (§10.1) — условия, вес среди подходящих, текст и выборы. Условия — таблица `[conditions]`:
`epochs`, `window = { from, until }` (`from` входит в окно, `until` — уже нет), `cities`,
`reputation = [{ faction, at_least, at_most }]`, `money = { at_least }` (наличные, рубли 1984 года),
`goods = [{ good, at_least }]`, `flags_set`, `flags_unset`, `npc` (человек не потерян и не в
отъезде), `timeline` (узлы появятся с генератором истории, до тех пор такое событие не
случается). У выбора свои `[choices.conditions]`, последствия `[choices.consequences]`
(`money`, `goods = [{ good, change }]`, `reputation = [{ faction, change }]`,
`contacts = [{ npc, relation, favours, away_days, lost }]`, `set_flags`, `clear_flags`,
`price_shocks = [{ good, city, factor, days }]`), текст исхода `outcome` и отложенные
продолжения `[[choices.follow_ups]]` (`event`, `after_days`, `chance` от 0 до 1).

Поля события сверх обязательных: `once = true` — случается за жизнь один раз; `cooldown_days` —
сколько дней повторяемое событие отдыхает (по умолчанию — из `event_rules.toml`); `sum` — сумма в
рублях 1984 года для `{sum}`; `price_of` — товар, чья цена на толкучке города подставляется в
`{price}`.

Как события приходят:

- каталог `events/<эпоха>/` — тоже условие: событие случается только в своей эпохе; события
  `zone/events/` — только в зоне;
- каждый спокойный день с вероятностью `daily_chance` случается одно из готовых событий,
  выбранное по весам; готово то, чьи условия выполнены, однократное ещё не было, а повторяемое
  отдохнуло;
- продолжение назначается в момент выбора с вероятностью `chance` и приходит через
  `after_days` дней, если его условия всё ещё выполнены, — иначе момент упущен;
- событие останавливает время до выбора и прочитанного исхода; торговать и класть деньги в это
  время нельзя;
- выбор доступен, только если выполнены его условия и у игрока есть деньги и товар, которые
  выбор забирает.

Последствие для человека делает его связью, если он ещё не знаком: `relation` — отношение
(плюс — расположение, минус — обида), `favours` — услуги (плюс — он должен игроку, минус — игрок
ему), `away_days` — уезжает на столько дней, `lost = true` — потерян навсегда.

В текстах работают подстановки `{npc}` (только при условии `npc`), `{price}` (только при
`price_of`) и `{sum}` (только при `sum`). Суммы подставляются в номинале текущей валюты вместе с
«р.», поэтому в конце фразы после подстановки точку не ставят: «по {price}», а не «по {price}.».

Пример §10.2 целиком лежит в `crates/speculant-core/tests/fixtures/content-min/events/stagnation/`:
`vodka_crate.toml` и его продолжение `vodka_man_returns.toml`. Начало примера:

```toml
title = "Ящик «Столичной»"
weight = 10
once = true
sum = 600
text = """
У магазина «Вино-Водка» мужик в спецовке тянет тебя за рукав: …
"""

[conditions]
epochs = ["stagnation"]
window = { from = "1985-05-17", until = "1985-09-01" }
cities = ["moscow"]
npc = "vodka_man"

[[choices]]
text = "Сдать участковому"
outcome = "Участковый доволен и записывает твою фамилию."

[choices.consequences]
reputation = [{ faction = "militia", change = 2 }, { faction = "traders", change = -3 }]
set_flags = ["snitched_1985"]

[[choices.follow_ups]]
event = "vodka_man_returns"
after_days = 180
chance = 0.5
```

### Заготовка и проверка

```
cargo xtask new-event <эпоха> <имя>
```

создаёт `data/events/<эпоха>/<имя>.toml` из заготовки, которая уже проходит проверку.

```
cargo run -p speculant-validate -- data --watch
```

проверяет весь каталог при каждом сохранении и печатает ошибки как «файл:строка: сообщение»:
синтаксис и схема TOML, битые ссылки на товары, города, людей, эпохи и события, флаги, которые
никто не ставит, выборы без последствий, исхода и продолжения, окна дат раньше 1984 года,
неизвестные подстановки и подстановки без значения (`{sum}` без `sum`, `{price}` без `price_of`),
последствия для человека, которые ничего не меняют. Та же проверка стоит в ядре: игра с битым контентом не запустится.

## Экраны

### Как устроен экран

Весь интерфейс — один узел `TextScreen` (`godot/src/text_screen/text_screen.gd`): буфер 80×25
ячеек, в каждой символ, цвет символа (0–15) и цвет фона (0–7) из палитры EGA
(`godot/src/text_screen/ega.gd`). Окна, рамки, тени и строка F-клавиш — функции поверх буфера:
`put`, `fill`, `box`, `shadow`, `fkeys`. Они повторяют класс `Scr` дизайн-книги, поэтому макет
книги и экран игры строятся одними и теми же операциями.

Узел рисует буфер глифами шрифта PxPlus IBM VGA 9×16 из Ultimate Oldschool PC Font Pack
(VileR, CC BY-SA 4.0, лицензия лежит рядом со шрифтом в `godot/assets/fonts/`). Логическое поле
720×400 растягивается по вертикали в 1,35 раза до 720×540: так текстовый режим VGA выглядел на
мониторе 4:3. Сглаживание, хинтинг и субпиксельное позиционирование шрифта выключены в параметрах
импорта `PxPlus_IBM_VGA_9x16.ttf.import`.

### Какие символы можно использовать

Только те, что есть в шрифте: их список — `godot/assets/fonts/glyphs.txt`, его пишет
`cargo xtask font-glyphs` из cmap шрифта. Кириллица, псевдографика рамок, « » „ “ ◄ ► ▓ ░ ↑ ↓
в шрифте есть. Треугольник ▶ (U+25B6) отсутствует — вместо него ►.

```
cargo xtask charset-check
```

проверяет строковые литералы `godot/src/**/*.gd` и весь текст `data/**` и для известных подмен
подсказывает замену.

### Эталоны макетов

Шесть макетов дизайн-книги — заставка, рынок, событие, управляющий, пейджер, итоги жизни —
сняты в `design/etalons/<экран>.screen`. Их не рисуют руками: `cargo xtask etalons` исполняет
скрипт дизайн-книги встроенным движком JavaScript (Boa) с минимальным DOM и записывает начальный
кадр каждого макета. Палитра CSS книги ложится в `design/etalons/palette.txt` и сверяется с
`ega.gd`.

Формат `.screen` — текст: 25 строк символов, пустая строка, 25 строк hex-цветов символов, пустая
строка, 25 строк hex-цветов фона. Каждая строка ровно 80 колонок.

Если дизайн-книга изменилась, эталоны пересоздаются той же командой и коммитятся вместе с книгой.
Гейт `cargo xtask etalons --check` падает, когда закоммиченные эталоны разошлись с книгой.

### Сверка экрана с эталоном

```
cargo xtask screen-check <экран>
```

запускает Godot безголово, рисует экран инструментом `godot/tools/dump_screen.gd` и сравнивает
буфер с эталоном. При расхождении команда называет слой (символы, цвет символов, цвет фона),
строку и колонку. Если рядом с эталоном лежит фикстура состояния `<экран>.view.json`, экран
рисуется по ней.

### Предел безголовой проверки

Безголовый Godot не рендерит пиксели, поэтому машинная сверка идёт по буферу символов и цветов,
а не по картинке. Как выглядят глифы, пропорции и цвета, проверяет человек по PNG:

```
cargo xtask screenshot <экран>
```

запускает Godot в окне и сохраняет `.tools/out/<экран>.png`. В CI на Linux снимок делается под
Xvfb и прикладывается к прогону как артефакт.
