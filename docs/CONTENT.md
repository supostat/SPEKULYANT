# Контент и экраны «Спекулянта» — руководство автора

Документ для тех, кто пишет данные игры и рисует экраны. Источник решений — `docs/SPEKULYANT.md`,
эталон интерфейса — `design/design-book.html`. Разделы о формате событий, товаров и городов
появятся вместе с форматом данных.

## Экраны

### Как устроен экран

Весь интерфейс — один узел `TextScreen` (`godot/src/text_screen/text_screen.gd`): буфер 80×25
ячеек, в каждой символ, цвет символа (0–15) и цвет фона (0–7) из палитры EGA
(`godot/src/text_screen/ega.gd`). Окна, рамки, тени и строка F-клавиш — функции поверх буфера:
`put`, `fill`, `box`, `shadow`, `fkeys`. Они повторяют класс `Scr` дизайн-книги, поэтому макет
книги и экран игры строятся одними и теми же операциями.

Узел рисует буфер глифами шрифта PxPlus IBM VGA 9×16 из Ultimate Oldschool PC Font Pack
(VileR, CC BY-SA 4.0, лицензия лежит рядом со шрифтом в `godot/assets/fonts/`). Логическое поле
720×400 растягивается по вертикали в 1,35 раза до 720×540: так текстовый режим VGA выглядел на
мониторе 4:3. Сглаживание, хинтинг и субпиксельное позиционирование шрифта выключены в параметрах
импорта `PxPlus_IBM_VGA_9x16.ttf.import`.

### Какие символы можно использовать

Только те, что есть в шрифте: их список — `godot/assets/fonts/glyphs.txt`, его пишет
`cargo xtask font-glyphs` из cmap шрифта. Кириллица, псевдографика рамок, « » „ “ ◄ ► ▓ ░ ↑ ↓
в шрифте есть. Треугольник ▶ (U+25B6) отсутствует — вместо него ►.

```
cargo xtask charset-check
```

проверяет строковые литералы `godot/src/**/*.gd` и весь текст `data/**` и для известных подмен
подсказывает замену.

### Эталоны макетов

Шесть макетов дизайн-книги — заставка, рынок, событие, управляющий, пейджер, итоги жизни —
сняты в `design/etalons/<экран>.screen`. Их не рисуют руками: `cargo xtask etalons` исполняет
скрипт дизайн-книги встроенным движком JavaScript (Boa) с минимальным DOM и записывает начальный
кадр каждого макета. Палитра CSS книги ложится в `design/etalons/palette.txt` и сверяется с
`ega.gd`.

Формат `.screen` — текст: 25 строк символов, пустая строка, 25 строк hex-цветов символов, пустая
строка, 25 строк hex-цветов фона. Каждая строка ровно 80 колонок.

Если дизайн-книга изменилась, эталоны пересоздаются той же командой и коммитятся вместе с книгой.
Гейт `cargo xtask etalons --check` падает, когда закоммиченные эталоны разошлись с книгой.

### Сверка экрана с эталоном

```
cargo xtask screen-check <экран>
```

запускает Godot безголово, рисует экран инструментом `godot/tools/dump_screen.gd` и сравнивает
буфер с эталоном. При расхождении команда называет слой (символы, цвет символов, цвет фона),
строку и колонку. Если рядом с эталоном лежит фикстура состояния `<экран>.view.json`, экран
рисуется по ней.

### Предел безголовой проверки

Безголовый Godot не рендерит пиксели, поэтому машинная сверка идёт по буферу символов и цветов,
а не по картинке. Как выглядят глифы, пропорции и цвета, проверяет человек по PNG:

```
cargo xtask screenshot <экран>
```

запускает Godot в окне и сохраняет `.tools/out/<экран>.png`. В CI на Linux снимок делается под
Xvfb и прикладывается к прогону как артефакт.
