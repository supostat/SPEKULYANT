# Контент и экраны «Спекулянта» — руководство автора

Документ для тех, кто пишет данные игры и рисует экраны. Источник решений — `docs/SPEKULYANT.md`,
эталон интерфейса — `design/design-book.html`.

## Формат данных

Решение 15.7: контент пишется в TOML, один файл на сущность, в любом текстовом редакторе. Имя
файла без `.toml` — идентификатор сущности: латиница в нижнем регистре, цифры и `_`, с буквы
(`chewing_gum.toml` → `chewing_gum`). На него ссылаются другие файлы.

### Раскладка `data/`

| Путь | Что лежит |
|---|---|
| `epochs/time.toml` | календарь эпох и часы игры (решение 15.3) |
| `epochs/<эпоха>.toml` | описание эпохи, её угроза и темп дрейфа репутации; у каждой эпохи календаря оно обязательно |
| `goods/<товар>.toml` | товар и его кривая цены |
| `cities/<город>.toml` | город, толкучка, множители цен, доступность |
| `routes.toml` | направления поездок |
| `economy/market.toml` | правила толкучки: разница цен, восстановление запаса, колебания |
| `economy/money.toml` | индекс цен, деноминация, курсы чеков и доллара |
| `money/<место>.toml` | место хранения денег: валюта, окно, процент, риск |
| `reputation.toml` | пределы репутации и долгов связей |
| `factions/<фракция>.toml` | фракция репутации (решение 15.6) |
| `event_rules.toml` | шанс события в спокойный день и отдых повторяемых событий |

| `business/rules.toml` | правила дел: шкала риска прогноза, черты сотрудников, шансы происшествий |
| `business/forms/<форма>.toml` | форма собственности и её окно дат |
| `business/kinds/<тип>.toml` | тип дела: точки, расходы, товар, политики |
| `business/policies/<политика>.toml` | политика управляющего и её варианты; имён шесть |
| `business/habits/<привычка>.toml` | привычка или слабость сотрудника |
| `life.toml` | правила жизни: шкала здоровья, старение, матрас, зачёт жилья, итоги, имена, пейджер |
| `housing/<жильё>.toml` | жильё и риск для денег под матрасом (решение 15.4) |
| `endings/<финал>.toml` | финал жизни и его заметка по эпохам |
| `biographies/<биография>.toml` | стартовая биография (решение 15.5) |
| `npc/<человек>.toml` | шаблон соперника, знакомого или того, кого можно нанять |
| `events/<эпоха>/<событие>.toml` | событие эпохи |
| `zone/rules.toml` | правила зоны и зоны эпох (решение 15.8) |
| `zone/services/<услуга>.toml` | услуга зоны за сигареты и чай |
| `zone/events/<событие>.toml` | событие зоны |
| `history/<узел>.toml` | исторический узел: окно дат, масштаб, исходы (§3.6) |
| `history/generator.toml` | генератор песочницы: начало, горизонт, промежутки (решение 15.9) |
| `history/post2004/<шаблон>.toml` | шаблон генератора песочницы |
| `sound/boot.toml` | мелодия заставки для пищалки PC-speaker |
| `balance.toml` | пороги объёма, баланса и покрытия для инструментов; игра его не читает |

Файл вне этой раскладки — ошибка: опечатка в имени каталога не пропадёт молча.

### Деньги и даты

Цены и суммы в данных — рубли 1984 года числом (`price = 160`, `price = 4.5`): реальная стоимость.
Ядро хранит их в копейках и само переводит в номинал дня; гиперинфляция и деноминация в товарах,
биографиях и событиях не пишутся. Единственное место номинала — `economy/money.toml`: там индекс
цен и курсы в рублях на ценнике по годам. Даты — `"ГГГГ-ММ-ДД"`, не раньше `"1984-01-01"`.

Деньги игрока лежат в своей валюте: наличные и вклады в рублях обесцениваются вместе с индексом,
чеки и доллары идут по курсу дня. Поэтому гиперинфляция бьёт ровно по тем, кто держит рубли
(§5.1).

### Товар, город, маршрут, биография, человек, эпоха

name = "Джинсы (фирма)"
short_name = "Джинсы"         # для окна «Карман»
category = "clothes"          # по категории город задаёт множитель
unit = "шт"
stock = 6                     # обычный запас на толкучке города
curve = [                     # цена в начале года; годы строго возрастают, до первой точки товара нет
  { year = 1984, price = 180 },
  { year = 1992, price = 60 },

### Мир: товары, города, люди, эпохи

Товары (решение 15.2) — 40 штук в восьми категориях; имя категории — то, к чему город цепляет
множитель:

| Категория | Что в ней |
|---|---|
| `clothes` | джинсы, кроссовки, кожа, варёнки, шапки, колготки |
| `electronics` | часы, видики, плееры, компьютеры, мобилы, пейджеры |
| `media` | пластинки, видео- и аудиокассеты, диски, журналы |
| `tobacco` | сигареты, сигары, зажигалки |
| `alcohol` | водка, коньяк, виски, «Рояль», пиво |
| `food` | сахар, кофе, икра, сервелат, бананы |
| `sweets` | жвачка, «Сникерсы», кола, шампунь — сладости и импорт |
| `prestige` | золото, «Жигули», «Мерседес», холодильник, хрусталь |

Опорные точки кривой — по чётным годам с 1984-го по 2004-й, цены — в рублях 1984 года, то есть
реальные: подешевевший в 1992-м импорт падает в кривой, а гиперинфляцию добавляет индекс. Товар,
которого ещё нет, начинает кривую в год появления: мобильный телефон — с 1994-го.

Города (решение 15.1) — десять, по одному на направление §4. Москва — точка отсчёта, без
множителей. Ленинград, Горький, Рига, Ташкент и Тбилиси открыты с начала, Берлин до 1990 года
только `connections_only_until`, Варшава, Стамбул и Пекин — с `opens`. Множитель меньше единицы —
категория в городе дешевле, больше — дороже. Маршрут в `routes.toml` односторонний: обратный путь —
отдельная запись.

Люди: соперник — шаблон со `strategy` и `capital` (пул — 20 шаблонов, из них в мир сид берёт от
`min_rivals` до `max_rivals`); знакомый — шаблон без стратегии, его дают биографии и события;
тот, кого можно нанять, — шаблон с таблицей `[employee]`. Биографии (решение 15.5) — пять открытых
и две закрытые: `party_son` открывает флаг `nomenklatura` (событие «Приглашение в райком»),
`ex_convict` — флаг выхода с зоны.

Эпоха в `epochs/<эпоха>.toml` говорит о себе одной строкой `summary` — закон, деньги и угроза,
— а угроза `threat` и темп дрейфа репутации действуют. Фракция без `from_epoch` есть с начала игры,
силовики — со стабилизации.

### Объём контента

Решение 15.11 и решения 15.1, 15.2 задают, сколько сущностей каждого вида должно быть в `data/`.
Числа лежат только в `balance.toml`:

```toml
[volume]
goods = 40
cities = 10
npc = 20                  # шаблоны соперников — люди со стратегией
zone_events = 40
post2004_templates = 20

[volume.events]           # события каждой эпохи из events/<эпоха>/
stagnation = 70
perestroika = 70
wild_market = 90
stabilization = 60
```

Проверка — `cargo xtask content-count <вид>`, где вид — `goods`, `cities`, `npc`,
`events:<эпоха>`, `zone-events` или `post2004-templates`. Команда загружает `data/` и падает, если
сущностей меньше порога: `content-count goods: 38 из 40`.

### Соперники

Соперник — шаблон из `npc/` со стратегией и капиталом (§8). Сид выбирает из таких шаблонов от
`min_rivals` до `max_rivals` человек и даёт каждому город; челноку — ещё второй город на открытом
маршруте. Торговец скупает излишек на толкучке своего города и продаёт в дефицит, челнок возит
товар туда, где он дороже, и возвращается порожняком; оба торгуют по тем же ценникам, что игрок,
и двигают запасы. Рэкетир и чиновник получают доход в день, банкир — процент первого числа.
Каждый день соперника может постичь судьба: зона на `prison_days` дней, гибель, депутатство;
капитал ниже `ruin_below` — разорение.

```toml
# rivals.toml — вероятности на день, деньги — рубли 1984 года
min_rivals = 10
max_rivals = 15
ruin_below = 20
prison_days = 1095

[strategies.trader]
trade_chance = 0.5            # торгует ли сегодня
lot = 3                       # штук за сделку
prison_chance = 0.0001        # ещё death_chance и deputy_chance

[strategies.racketeer]
daily_income = 3

[strategies.banker]
annual_percent = 25
business_chance = 0.03        # шанс в месяц открыть точку своего дела
```

Соперник со `business_chance` первого числа может открыть точку дела в своём городе — тип
выбирает случай среди тех, что можно открыть в этот день, где точек ещё не предел и на что у
него хватает денег с запасом `rival_reserve` из `business/rules.toml`. Его дела приносят месяц по
тому же расчёту, что у игрока, только грубее: политики по умолчанию, управляющий средней хватки,
без происшествий. Точки соперников того же типа в городе делят выручку игрока (`competition`).

Событие с соперником пишется без имени: `[conditions] rival = { strategy, relation_at_least,
relation_at_most, offended_days }` — кто именно участвует, при начале события выбирает сид среди
подходящих соперников в деле, и `{npc}` подставляет его имя. Последствие `rival = { relation,
favours }` меняет его память об игроке; обида помнится с того дня, как отношение ушло в минус, и
условие `offended_days = 180` приводит «кинутого партнёра» ровно через полгода. Условие `rival`
бывает только у события целиком, последствие `rival` — только при нём. Условие `npc` на шаблон
соперника выполняется, только если этот соперник есть в мире и в деле.

### Дела

Своё дело (§7) — тип в городе: первая точка открывает дело, следующие расширяют его до
`max_points`. Дело носит форму собственности своего дня — из форм типа ту, что открыта и
началась позже всех: цех варёнок 1986 года — подпольный цех, в 1988-м он сам становится
кооперативом. Формы типа не должны оставлять разрывов: если форма закрывается (`until`), в этот
день должна быть открыта следующая. Деньги — рубли 1984 года за точку в месяц.

```toml
# business/forms/cooperative.toml
title = "Кооператив"
from = "1988-05-26"
# until = "1999-07-01" — с этой даты форма закрыта (так у ТОО); без until открыта всю жизнь
raid = 0                      # сдвиг уровня наезда: подпольному цеху +1
racket_share = 0.6            # доля наездов от рэкета, остальное — проверки
tax = 0.05                    # налог — доля выручки

# business/kinds/kiosks.toml
title = "Ларьки"
forms = ["cooperative", "partnership", "company"]
point_cost = 5000             # цена точки
max_points = 5
rent = 30                     # аренда точки в месяц; у челнока её нет
wages = 60                    # зарплата персонала точки по рынку
goods = { cigarettes = 600, vodka = 10 }  # штуки в месяц по средней цене города
margin = 0.25                 # доля продаж, которая остаётся выручкой
income = 0                    # выручка без товара — оборот банка
raid = 1                      # сдвиги уровней наезда и воровства у такого дела
theft = 0
policies = ["markup", "roof", "purchase", "night_trade", "inspection", "wage"]
```

Выручка точки — продажи товара по средней цене города, умноженные на `margin`, плюс `income`;
она растёт на `skill_step` за каждое деление хватки управляющего выше середины шкалы,
сдвигается политиками и привычками и делится с конкурентами. Товар, которого ещё нет в продаже,
ничего не приносит, поэтому выручка дела следует кривым цен.

Политик шесть, их роль в расчёте задаёт ядро, а данные — подписи, варианты и сдвиги прогноза.
Имя файла — одно из `markup`, `roof`, `purchase`, `night_trade`, `inspection`, `wage`. Вариант
сдвигает выручку (`revenue`, проценты), уровни наезда и воровства (`raid`, `theft`) и
лояльность управляющего (`loyalty`). У вариантов крыши обязательно `roof_percent` (доля выручки
крыше, ноль — крыши нет), у вариантов проверки — `inspection` (`pay` — откупиться, `call` —
звонить хозяину, `close` — закрыться), у вариантов зарплаты — `wage_percent` от рынка; у других
политик этих полей нет.

```toml
# business/policies/inspection.toml
title = "При проверке"
default = "звонить мне"       # вариант нового дела

[[options]]
label = "платить"
inspection = "pay"
raid = -1

[[options]]
label = "звонить мне"
inspection = "call"

# business/habits/brother_in_militia.toml
text = "Брат в милиции."
raid = -1                     # те же сдвиги, что у вариантов политик
skill_loss_chance = 0         # шанс в месяц пропить деление хватки
```

Прогноз на месяц с экрана управляющего — это уровни, по которым дело и живёт. Наезд:
`base_raid` правил, тип, форма, политики и привычки; воровство: `base_theft`, честность
управляющего против середины шкалы, тип, политики и привычки; оба — в пределах `risk_levels`, и
у каждого уровня свой шанс беды в месяц. Без управляющего дело стоит и платит только аренду.

Первого числа дело считает прошлый месяц: выручка за рабочие дни с колебанием `revenue_noise`,
доля крыше и налог с неё, аренда за все дни, зарплата за дни с управляющим, откупы, недостача
(`theft_share` выручки, если управляющий проворовался) — итог приходит в наличные. Убыток,
который нечем покрыть, забирает все наличные и закрывает дело.

Каждый день дело с управляющим может попасть в происшествие: `racket` и `inspection` делят шанс
уровня наезда по `racket_share` формы, `roof_raise` — только при крыше, `departure` и `betrayal`
— по лояльности (`departure_chances`, `betrayal_chances`), `fire` — `fire_chance`. Крыша
закрывает рэкет сама, проверку закрывает вариант `pay` или `close`; всё остальное выходит за
политики и приходит событием с полем `incident` (раздел «Событие»). Если готового события про
это происшествие нет, оно проходит без последствий. Уволенный обижается на `fired_relation`.

### Жизнь

Жизнь (§11) начинается 1 января 1984 года с биографии. Решение 15.5: пять биографий открыты с
начала (`starts_unlocked = true`), две открываются флагом, поставленным в одной из жизней, —
закрытой биографии нужны `unlocked_by_flag` и подсказка `unlock_hint`, и флаг должен ставить
хотя бы одно последствие. Итоги называют открытое, и следующая жизнь сеанса может с него
начаться; на диск открытия сохранит метапрогрессия.

```toml
# biographies/student.toml
title = "Студент"
description = "Общежитие, иностранцы-сокурсники, мало денег."
start_city = "moscow"
start_cash = 150
contacts = ["kofi", "officer_syomin"]
age = { from = 19, to = 22 }  # сколько лет 1 января 1984 года — выбирает сид
housing = "dorm_bed"
obituary = "Начинал фарцовщиком в студенческом общежитии."  # первая фраза некролога
starts_unlocked = true
# unlocked_by_flag = "nomenklatura" и unlock_hint = "…" — у закрытой

# housing/communal_room.toml
title = "Комната в коммуналке"
price = 2500                  # без price жильё не продаётся — его дают биография и события
# on_sale_from = "1992-07-01" — с этой даты
stash_risk = 0.04             # шанс в месяц лишиться денег под матрасом
```

Имя персонажа сид собирает из пулов `[names]` в `life.toml`. Здоровье (решение 15.4) — скрытая
шкала до `health_max`, игрок видит её словами `health_states`; с возраста `aging_from` в каждый
день рождения она убывает на `aging_per_year`, последствие `health` события двигает её, а на нуле
жизнь кончается финалом `health_ending`. Жильё покупается командой за наличные, прежнее идёт в
зачёт по `resale_share` своей цены; первого числа с шансом жилья кража или пожар уносят
`stash_loss_share` денег из места с `home = true`. Семья — только события и флаги.

Пейджер (§13.2), позже мобила, — устройство из кармана: первое из `[pager] devices`, чей товар
лежит у игрока. Пока оно при игроке, в его ленту приходят месячные отчёты и происшествия дел,
новости узлов истории и потери под матрасом; срочные — происшествия, которые ждут хозяина, и
потери. Лента держит последние `messages` сообщений; в заголовке `{number}` — номер абонента
из сида жизни.

```toml
# life.toml
[pager]
messages = 12
devices = [
  { good = "mobile_phone", title = "МОБИЛА · номер {number}" },
  { good = "pager", title = "ПЕЙДЖЕР · абонент {number}" },
]
```

Звонок связи начинает с игроком готовое событие с условием `npc` на этого человека — по весам,
как событие дня; если такого события сейчас нет, человек не берёт трубку. Потерянному и
уехавшему не дозвониться.

Финал (§11.2) приходит последствием `end_life = "<финал>"` (после того, как игрок прочтёт
исход), от здоровья или по своей воле — командой ухода. Итоги — заметка той газеты или того
суда, что пишет о финале в эту эпоху: `sources` нужна для каждой эпохи календаря.

```toml
# endings/emigration.toml
kind = "departure"            # death, prison, ruin или departure
title = "Эмигрировать"
voluntary = true              # выбирает игрок; бывает только у departure
available_from = "1990-01-01" # только у добровольного
capital_label = "Вывезено за границу"
headline = "УЕХАЛ: {NAME}"
text = "{date} улетел из Шереметьева в один конец."

[sources]
stagnation = "«ВЕЧЕРНЯЯ МОСКВА»"
wild_market = "«МОСКОВСКИЙ КОМСОМОЛЕЦ»"
```

Подстановки финала: `{name}`, `{NAME}` (прописными), `{born}` и `{ended}` (годы), `{date}`
(«3 ноября 1997»), `{age}`. Текст итогов — `obituary` биографии, фраза `business_sentence` о
первом деле (`{year}`, `{business}`) и `text` финала. Капитал — деньги, товар, точки дел и жильё;
с `capital_in_dollars_from` он показывается в долларах. Страницу газеты выбирает сид из
`newspaper_pages`.

Кончившаяся жизнь оставляет следующим (§11.3, решение 15.10): открытые биографии; записную
книжку — почём покупались и продавались товары, последнюю запись о каждом знакомом и сопернике,
лучшую прибыльную сделку с товаром; исторические узлы, которые она видела, — из них стартовые
слухи, если узел ждётся в этом году или в следующем; строку в рекордах своего режима — ironman
или свободного. Каждая таблица рекордов держит `records_size` богатейших жизней.

### Зона

Зона (§12, решение 15.8) — отдельный режим. Срок даёт последствие `sentence_months` события на
воле: игрока снимают с улицы и с дороги, и неделя зоны (`week_days` дней) идёт за время одного
дня на воле. Срок длиннее `longest_sentence_months` кончает жизнь финалом `life_ending` (его
`kind` — `prison`); в зоне новый срок от дела на воле прибавляется к нынешнему. Из зоны не
торгуют, не ездят, не трогают деньги на вкладах, не распоряжаются делами, не звонят, не покупают
жильё и не уходят на покой.

```toml
# zone/rules.toml — шансы в неделю, деньги — рубли 1984 года
week_days = 7
longest_sentence_months = 120
life_ending = "prison"
event_chance = 0.25           # событие зоны в конце недели
health_loss_chance = 0.15     # зона подтачивает здоровье на health_loss
health_loss = 2
authority_levels = ["первоход", "мужик", "уважаемый", "блатной", "авторитет"]
start_authority = 1
idle_authority_chance = 0.04  # кто не ходит на промзону, растёт в авторитете
parole_max_authority = 3      # выше — УДО не дают
parole_retry_weeks = 26       # после отказа в УДО
release_flag = "released_from_zone"  # ставит выход; им открывается «Бывший сиделец»
ties_faction = "bandits"      # связи «оттуда»: репутация на выходе по уровню авторитета
ties = [0, 0, 1, 2, 3]

[parcel]                      # передача с воли за наличные
price = 30
contents = { cigarettes = 20, tea = 5 }

[trustees]                    # доверенные лица: шанс в месяц отсидки по делениям черт
vanish_chances = [0.25, 0.12, 0.05, 0.02, 0.0]  # по лояльности — исчезнуть с выручкой
steal_chances = [0.6, 0.35, 0.15, 0.05, 0.0]    # по честности — воровать
steal_share = 0.5

[camps.wild_market]           # зона каждой эпохи календаря
title = "Колония общего режима, Тверская область"
work_pay = 1                  # пачек сигарет за неделю на промзоне
parcel_weeks = 4              # передача не чаще раза в столько недель
parole_after = 0.5            # УДО — после такой доли срока
parole_chance = 0.4           # шанс УДО при полной трудовой характеристике
bribe = 3000                  # выход за взятку; без bribe зона на волю не продаёт

# zone/services/infirmary.toml
title = "Больничка"
price = { cigarettes = 10 }   # сигареты и чай, хотя бы что-то одно
health = 10                   # и/или authority = 1
```

Промзона платит сигаретами и пишет трудовую характеристику: шанс УДО — `parole_chance`, умноженный
на долю отработанных недель. Делами на воле управляют те же управляющие: первого числа, пока
хозяин сидит, каждый по лояльности и честности ведёт дело честно, ворует `steal_share` выручки
или исчезает со всей выручкой и пропадает из связей. Происшествия, вышедшие за политики, находят
хозяина и в зоне.

События зоны лежат в `zone/events/` и приходят только в зоне — в конце недели с шансом
`event_chance` и продолжениями. Им доступно условие `authority = { at_least, at_most }` (уровни
от 1) и последствие `zone = { cigarettes, tea, authority, term_months, amnesty }`: минус сигарет
или чая — отдать, и выбор доступен, только если их хватает; `term_months` прибавляет к сроку или
скащивает его; `amnesty = true` выпускает на волю, когда игрок прочтёт исход. Амнистия — событие
зоны с окном дат указа или событие исторического узла (раздел «История»). События зоны не бывают
дорожными и не дают `sentence_months`, а события на воле не знают `authority` и `zone`.

### История

История (§3.6) плавает по сиду: при создании мира каждый узел `history/` получает день в своём
окне, масштаб из разброса и исход по весам. Окно лежит внутри одной эпохи — рамки эпох не
плавают; окно в один день не плавает совсем (деноминация — рамка номинала). В свой день узел
пишет новость исхода в ленту, ставит его флаги, сдвигает цены шоками — множитель `factor`
возводится в степень масштаба — и начинает событие исхода, если оно готово: на воле — событие
эпохи, в зоне — событие зоны. Дорожное событие и событие происшествия узел не начнёт.

```toml
# history/mmm.toml
title = "МММ"
window = { from = "1994-07-01", until = "1994-09-01" }  # день выбирает сид
scale = { from = 0.8, to = 1.3 }  # без scale масштаб не плавает

[[outcomes]]                      # альтернативы: хотя бы одна
weight = 3
news = "«МММ» прекратила выплаты: у офиса на Варшавке толпа."
price_shocks = [{ good = "vodka", factor = 1.2, days = 30 }]  # как у последствий
event = "mmm_queue"               # событие в день узла
set_flags = ["mmm_collapsed"]

[[outcomes]]
weight = 1
news = "«МММ» объявила новый выпуск билетов: пирамида держится."
set_flags = ["mmm_lasted"]
```

Решение 15.9: после 2004 года историю продолжает генератор. Он шагает от `from` до `until`
промежутками из `gap_days` и на каждом шаге ставит по весам один из шаблонов `history/post2004/`,
отдохнувших свои `rest_days`; если все отдыхают, шаг пуст. Исторический узел не может зайти за
начало генератора, а имя узла не совпадает с именем шаблона.

```toml
# history/generator.toml
from = "2005-01-01"
until = "2061-01-01"
gap_days = { from = 150, to = 540 }

# history/post2004/goods_ban.toml — исходы такие же, как у исторического узла
title = "Запрет товара"
weight = 2
rest_days = 730
scale = { from = 0.8, to = 1.4 }
```

Условие события `timeline = "<узел>"` выполняется, когда узел уже случился, — для шаблона
генератора хотя бы раз; исход узла различают его флаги.

### Поездки

Направление — маршрут из `routes.toml` из текущего города. Город с `opens` до этой даты закрыт и
в списке направлений не показывается; до `connections_only_until` ехать можно только по блату —
за услугу первого знакомого, который согласится помочь (не обижен, не в отъезде и не ждёт уже
слишком много услуг). Проезд `fare` платится наличными сразу, `days` — дни в пути; в дороге нет
ни толкучки, ни вкладов. Каждый день пути с вероятностью `road_daily_chance` случается одно из
дорожных событий маршрута по весам `road_events`. Дорожное событие помечается `road = true`,
случается только в пути и должно стоять хотя бы на одном маршруте; обычные события в пути не
случаются. Прибытие и любое событие останавливают перемотку; если событие пришло в последний
день пути, игрок приезжает, когда прочтёт исход.

Фракций шесть (решение 15.6): `bandits`, `militia`, `officials`, `traders`, `people`, `siloviki`.
На них ссылаются условия и последствия событий (`reputation = [{ faction, … }]`), люди и угрозы
эпох; неизвестная фракция — ошибка валидатора, как и граница условия за пределом `limit`.

### Толкучка, индекс и курсы

```toml
# economy/market.toml — доли от средней цены или от обычного запаса товара
spread = 0.08       # разница цен покупки и продажи
recovery = 0.15     # доля отклонения запаса от обычного, которую рынок выбирает за день
daily_noise = 0.1   # случайное колебание запаса за день, по сиду мира

# economy/money.toml — рубли на ценнике в начале года; после деноминации — новые рубли
denomination = { date = "1998-01-01", factor = 1000 }
inflation = [                 # рублей на ценнике за рубль 1984 года на 1 января; 1984 год — единица
  { year = 1984, rubles = 1 },
  { year = 1992, rubles = 2.6 },  # скачок либерализации идёт в течение 1992 года
  { year = 1993, rubles = 70 },
  { year = 1997, rubles = 10000 },
  { year = 1998, rubles = 11 },   # новые рубли: деноминация 1 января 1998 года
]
checks_rate = [{ year = 1984, rubles = 2 }]   # рублей за чек ВПТ
dollar_rate = [{ year = 1984, rubles = 3 }]   # рублей за доллар
```

Между опорными точками кривые товаров, индекс и курсы меняются в одно и то же число раз за
день. Цена штуки на толкучке — кривая товара, множитель города, шоки событий и запас: пустой рынок
продаёт вдвое дороже, заваленный — дешевле в разы; каждая следующая штука в одной сделке дороже
при покупке и дешевле при продаже.

### Событие

Событие (§10.1) — условия, вес среди подходящих, текст и выборы. Условия — таблица `[conditions]`:
`epochs`, `window = { from, until }` (`from` входит в окно, `until` — уже нет), `cities`,
`reputation = [{ faction, at_least, at_most }]`, `money = { at_least }` (наличные, рубли 1984 года),
`goods = [{ good, at_least }]`, `flags_set`, `flags_unset`, `npc` (человек не потерян и не в
отъезде), `timeline` (узел истории уже случился — раздел «История»). У выбора свои `[choices.conditions]`, последствия `[choices.consequences]`
(`money`, `goods = [{ good, change }]`, `reputation = [{ faction, change }]`,
`contacts = [{ npc, relation, favours, away_days, lost }]`, `set_flags`, `clear_flags`,
`price_shocks = [{ good, city, factor, days }]`, `business`, `health`, `sentence_months`, `zone`,
`end_life`), текст исхода
`outcome` и отложенные продолжения `[[choices.follow_ups]]` (`event`, `after_days`, `chance` от 0
до 1).

Поля события сверх обязательных: `once = true` — случается за жизнь один раз; `road = true` —
дорожное событие (раздел «Поездки»); `cooldown_days` —
сколько дней повторяемое событие отдыхает (по умолчанию — из `event_rules.toml`); `sum` — сумма в
рублях 1984 года для `{sum}`; `price_of` — товар, чья цена на толкучке города подставляется в
`{price}`; `incident` — событие происшествия с делом (раздел «Дела»): `racket`, `inspection`,
`roof_raise`, `departure`, `betrayal` или `fire`; `rare = true` — редкое событие: прогон покрытия
может его не встретить (раздел «Заготовка и проверка»), причина — комментарием над пометкой.

Событие происшествия не разыгрывается в спокойный день: оно приходит, только когда дело попало
в это происшествие и политика его не закрыла, — дома или в дороге, по готовым событиям эпохи
про это происшествие и их весам. Дорожным оно не бывает, в зоне его нет. Только у него есть
последствие `business = { policies = [{ policy, option }], manager_leaves, closed_days, lost }`:
вариант политики по подписи (если у дела такая политика есть), уход управляющего, закрытие на
`closed_days` дней, потеря дела.

Как события приходят:

- каталог `events/<эпоха>/` — тоже условие: событие случается только в своей эпохе; события
  `zone/events/` — только в зоне;
- каждый спокойный день с вероятностью `daily_chance` случается одно из готовых событий,
  выбранное по весам; готово то, чьи условия выполнены, однократное ещё не было, а повторяемое
  отдохнуло;
- продолжение назначается в момент выбора с вероятностью `chance` и приходит через
  `after_days` дней, если его условия всё ещё выполнены, — иначе момент упущен;
- событие останавливает время до выбора и прочитанного исхода; торговать и класть деньги в это
  время нельзя;
- выбор доступен, только если выполнены его условия и у игрока есть деньги и товар, которые
  выбор забирает;
- у каждого события есть выбор, доступный всегда: без своих условий и не забирающий денег,
  товара и запаса зоны сверх того, что обещают условия события, — иначе событие могло бы
  запереть время; валидатор это проверяет;
- продолжение цепочки — тоже событие эпохи, и без условий оно попало бы в розыгрыш спокойного
  дня. Поэтому выбор, который назначает продолжение, ставит флаг, продолжение требует его
  `flags_set` и снимает в своих выборах, а вес у продолжения — 1.

Последствие для человека делает его связью, если он ещё не знаком: `relation` — отношение
(плюс — расположение, минус — обида), `favours` — услуги (плюс — он должен игроку, минус — игрок
ему), `away_days` — уезжает на столько дней, `lost = true` — потерян навсегда.

В текстах работают подстановки `{npc}` (только при условии `npc`), `{price}` (только при
`price_of`), `{sum}` (только при `sum`), `{business}` и `{manager}` — дело и его управляющий
(только при `incident`). Подстановки снимаются в момент, когда событие случилось: исход
«{manager} собирает вещи» читается с именем, хотя управляющий уже ушёл. Суммы подставляются в номинале текущей валюты вместе с
«р.», поэтому в конце фразы после подстановки точку не ставят: «по {price}», а не «по {price}.».

Пример §10.2 целиком лежит в `crates/speculant-core/tests/fixtures/content-min/events/stagnation/`:
`vodka_crate.toml` и его продолжение `vodka_man_returns.toml`. Начало примера:

```toml
title = "Ящик «Столичной»"
weight = 10
once = true
sum = 600
text = """
У магазина «Вино-Водка» мужик в спецовке тянет тебя за рукав: …
"""

[conditions]
epochs = ["stagnation"]
window = { from = "1985-05-17", until = "1985-09-01" }
cities = ["moscow"]
npc = "vodka_man"

[[choices]]
text = "Сдать участковому"
outcome = "Участковый доволен и записывает твою фамилию."

[choices.consequences]
reputation = [{ faction = "militia", change = 2 }, { faction = "traders", change = -3 }]
set_flags = ["snitched_1985"]

[[choices.follow_ups]]
event = "vodka_man_returns"
after_days = 180
chance = 0.5
```

### Заготовка и проверка

```
cargo xtask new-event <эпоха> <имя>
```

создаёт `data/events/<эпоха>/<имя>.toml` из заготовки, которая уже проходит проверку.

```
cargo run -p speculant-validate -- data --watch
```

проверяет весь каталог при каждом сохранении и печатает ошибки как «файл:строка: сообщение»:
синтаксис и схема TOML, битые ссылки на товары, города, людей, эпохи и события, флаги, которые
никто не ставит, выборы без последствий, исхода и продолжения, окна дат раньше 1984 года,
неизвестные подстановки и подстановки без значения (`{sum}` без `sum`, `{price}` без `price_of`),
последствия для человека, которые ничего не меняют, события без выбора, доступного всегда. Та
же проверка стоит в ядре: игра с битым контентом не запустится.

```
cargo run -p speculant-validate -- data --strict [--coverage coverage.json]
```

`--strict` ищет события, которые не случатся ни в одной жизни: окно или условие `epochs` вне
дней эпохи каталога, окно, которое кончается раньше узла из `timeline`, флаг, который ставят
только недостижимые события или ставят позже последнего дня события, событие зоны, когда ни один
достижимый выбор не даёт срока, соперник со стратегией, которой нет ни у одного шаблона `npc/`.
Флаг ставят исходы узлов истории (с начала окна), шаблоны песочницы (с начала генератора) и
выборы достижимых событий (с их самого раннего дня); выход из зоны ставит свой флаг. Там же —
мёртвые цепочки: продолжение требует флага, который назначивший его выбор снимает, или не терпит
флага, который выбор ставит; через `after_days` дней оно выпадает из своих дней; событие зоны
назначено выбором на воле, который не даёт срока; узел истории начинает событие вне его дней.

`--coverage` сверяет данные с покрытием прогона симулятора: событие, которое ни разу не
сработало, — ошибка, если оно не помечено `rare = true`; покрытие короче `[coverage] lives` или
снятое с других данных — тоже ошибка. Всё вместе одной командой:

```
cargo xtask coverage-check
```

— прогон `[coverage] lives` жизней с сидом `[balance] seed` и любопытством `[coverage]
curiosity`, строгая проверка и сверка покрытия.

### Баланс и симулятор

Симулятор проживает жизни ботов на настоящем ядре и `data/` — день за днём, в зоне неделя за
неделей — до финала или до первого дня бесконечной эпохи:

```
cargo run -p speculant-sim -- --lives 600 --seed 1 [--strategy hoarder] [--threads 8] \
    [--report report.json] [--coverage coverage.json] [--curiosity 0.1]
```

Стратегии идут по кругу, биографии, открытые с начала, — по кругу внутри стратегии, сид каждой
жизни берётся из сида прогона, поэтому итог не зависит от числа потоков:

- `random` — покупает, продаёт и ездит наугад: точка отсчёта;
- `arbitrage` — везёт товар туда, где он даст больше всего за день пути, а если везти нечего —
  едет порожняком туда, откуда поездка окупит переезд;
- `hoarder` — помнит кривые цен: копит товар, который за два года подорожает сильнее всех, и
  продаёт, когда прогноз пошёл вниз;
- `entrepreneur` — возит товар, открывает самую дорогую точку, на которую наличных хватает в
  полтора раза, и ставит управляющего;
- `cautious` — ставит половину на маршруты в день пути, держит половину денег в месте с самым
  скромным процентом и выбирает наименее опасное;
- `reckless` — ставит всё, хватает самый денежный выбор, несёт деньги туда, где процент выше, и
  откупается из зоны.

Отчёт — кривая выживания по годам; по каждой эпохе — жизне-годы, беды (смерть, срок, разорение;
эмиграция и покой бедой не считаются) на жизне-год, дни жизни на одно событие и капитал стратегий
к её концу; капитал на конец жизни, финалы и покрытие событий: сколько раз сработало каждое и к
какой жизни прогон дал всё своё покрытие. `--coverage` пишет покрытие в JSON для валидатора.

Манера бота сама не выбирает вложений, отказов и долгов — их выгода прячется в продолжениях,
которых бот не видит. Поэтому в прогоне покрытия боты любопытны: в доле `--curiosity` решений бот
берёт наугад любой доступный выбор, кроме того, что кончает жизнь. Любопытство тянет свой поток
случая, и без него (по умолчанию доля — ноль) жизни идут так же, как шли; замер баланса всегда
идёт без любопытства.

Пороги сняты калибровкой от базы и лежат в `balance.toml` со строкой происхождения:

```toml
# calibrated: seed 1, lives 600, 2026-10-19
[balance]
seed = 1                  # прогон cargo xtask balance-check
lives = 200
breaking_medians = 20.0   # медиана капитала стратегии к концу эпохи — не больше стольких общих

[balance.mortality]       # бед на жизне-год — не больше
stagnation = 0.02

[balance.quiet_days]      # дней жизни на одно событие — не больше
stagnation = 20.0

[coverage]
lives = 1200              # столько жизней прогоняет валидатор покрытия
curiosity = 0.1           # доля решений бота наугад в прогоне покрытия
```

Порог есть у каждой эпохи, кроме бесконечной. Сверка —
`cargo xtask balance-check <эпоха|all>`: прогон `[balance] lives` жизней всеми стратегиями и
нарушенные пороги построчно: «perestroika: медиана капитала entrepreneur к концу эпохи — 107.97
общих медиан, порог 20.00». Эпоха, в которой жили, а событий не было вовсе, нарушает порог тишины
при любом его значении. CI гоняет двести жизней на каждом пуше; когда события эпохи написаны и её
сверка зелёная, `cargo xtask balance-check <эпоха>` встаёт в CI рядом.

### Мелодия заставки

`sound/boot.toml` — напев, который пищалка PC-speaker играет на заставке, одним голосом, нота за
нотой:

```toml
beat_ms = 150
notes = [
  { pitch = "E5", beats = 2 },
  { pitch = "B4", beats = 1 },
  { pitch = "rest", beats = 2 },
]
```

`pitch` — нота научной нотацией в октавах 1–8 («E5», «F#4», «Bb3») или `rest` — пауза; `beats` —
длина в долях, доля длится `beat_ms` миллисекунд. Ядро переводит ноты в тоны равномерной
темперации от ля первой октавы 440 Гц, округляя частоту до целых герц, как таймер PC-speaker, и
отдаёт их в снимке лобби (`boot_melody`). Загрузка отвергает неизвестную ноту, нулевую долю или
длину и пустую мелодию — с номером строки.

## Экраны

### Как устроен экран

Весь интерфейс — один узел `TextScreen` (`godot/src/text_screen/text_screen.gd`): буфер 80×25
ячеек, в каждой символ, цвет символа (0–15) и цвет фона (0–7) из палитры EGA
(`godot/src/text_screen/ega.gd`). Окна, рамки, тени и строка F-клавиш — функции поверх буфера:
`put`, `fill`, `box`, `shadow`, `fkeys`. Они повторяют класс `Scr` дизайн-книги, поэтому макет
книги и экран игры строятся одними и теми же операциями.

Узел рисует буфер глифами шрифта PxPlus IBM VGA 9×16 из Ultimate Oldschool PC Font Pack
(VileR, CC BY-SA 4.0, лицензия лежит рядом со шрифтом в `godot/assets/fonts/`). Логическое поле
720×400 растягивается по вертикали в 1,35 раза до 720×540: так текстовый режим VGA выглядел на
мониторе 4:3. Окно открывается с наибольшим целым увеличением этого кадра, какое влезает в рабочую
область экрана (на 4K-экране с Retina — ×3), а F11 или Alt+Enter переключают полный экран; целое
увеличение держит глифы чёткими. Сглаживание, хинтинг и субпиксельное позиционирование шрифта выключены в параметрах
импорта `PxPlus_IBM_VGA_9x16.ttf.import`.

### Какие символы можно использовать

Только те, что есть в шрифте: их список — `godot/assets/fonts/glyphs.txt`, его пишет
`cargo xtask font-glyphs` из cmap шрифта. Кириллица, псевдографика рамок, « » „ “ ◄ ► ▓ ░ ↑ ↓
в шрифте есть. Треугольник ▶ (U+25B6) отсутствует — вместо него ►.

```
cargo xtask charset-check
```

проверяет строковые литералы `godot/src/**/*.gd` и весь текст `data/**` и для известных подмен
подсказывает замену.

### Эталоны макетов

Шесть макетов дизайн-книги — заставка, рынок, событие, управляющий, пейджер, итоги жизни —
сняты в `design/etalons/<экран>.screen`. Их не рисуют руками: `cargo xtask etalons` исполняет
скрипт дизайн-книги встроенным движком JavaScript (Boa) с минимальным DOM и записывает начальный
кадр каждого макета. Палитра CSS книги ложится в `design/etalons/palette.txt` и сверяется с
`ega.gd`.

Формат `.screen` — текст: 25 строк символов, пустая строка, 25 строк hex-цветов символов, пустая
строка, 25 строк hex-цветов фона. Каждая строка ровно 80 колонок.

Если дизайн-книга изменилась, эталоны пересоздаются той же командой и коммитятся вместе с книгой.
Гейт `cargo xtask etalons --check` падает, когда закоммиченные эталоны разошлись с книгой.

### Сверка экрана с эталоном

```
cargo xtask screen-check <экран>
```

запускает Godot безголово, рисует экран инструментом `godot/tools/dump_screen.gd` и сравнивает
буфер с эталоном. При расхождении команда называет слой (символы, цвет символов, цвет фона),
строку и колонку. Если рядом с эталоном лежит фикстура состояния `<экран>.view.json`, экран
рисуется по ней.

### Экран без макета и путь игрока

```
cargo xtask screen-smoke <экран|all>
```

рисует экран без эталона безголово на снимке настоящего ядра и проверяет, что Godot не сообщил
ошибок, а строка F-клавиш стоит на месте во всю ширину; `all` — все такие экраны. Снимок берётся
тот, который экран получает в игре: главное меню, новая жизнь, рекорды и записная книжка — лобби
пустого каталога игрока, зона — моряк после цепочки «Сигнал» → «Проверка ОБХСС» → «Отпираться»,
остальные — новая жизнь студента.

```
cargo xtask ui-flow-smoke
```

гоняет инструментом `godot/tools/ui_flow.gd` клавиатурный путь игрока по настоящему ядру в чистом
каталоге игрока: заставка → главное меню → новая жизнь (студент, свободный режим, сид 7) → рынок,
F2 и окно количества, пауза, событие с выбором, F4 поездка → дела, связи и пейджер, где время
стоит → меню выхода и сохранение в слот → «Abort, Retry, Fail?» и F в главное меню → загрузка
слота → A — выход из игры; после шагов сверяется буфер экрана. Клавиши проходят через
`godot/src/input/keymap.gd` (F1–F10, стрелки, цифры, буквы, пробел, +/−, Esc, Enter, Backspace,
Del, PgUp/PgDn, мышь по строке F-клавиш и строкам окон) в действия экранов, а
`godot/src/screens/router.gd` держит стек экранов сеанса: верхний рисуется и получает действия,
жизнь стоит на экране режима, который называет ядро, событие ложится поверх модальным окном и
снимается, когда исход прочитан.

### Звук и CRT

Пищалка PC-speaker — `godot/src/sound/speaker.gd`: одноголосая прямоугольная волна
(`square_synth.gd`) через `AudioStreamGenerator`, как настоящий динамик IBM PC с таймером. Она
играет мелодию заставки из снимка лобби и бипы интерфейса, которые подаёт роутер: событие легло
поверх экрана, на пейджер пришло новое сообщение, ядро отказало в команде. Новый звук сменяет
недоигранный — голос у пищалки один.

CRT-эффект — `godot/src/crt/crt.gdshader` на прямоугольнике во весь кадр поверх экрана: строки
развёртки, лёгкое свечение люминофора и виньетка, без изгиба — текст читается так же. Оба, как и
полный экран, переключаются в «Настройках» главного меню и меню выхода и сохраняются в
`user://settings.cfg`: CRT по умолчанию выключен, пищалка включена, игра идёт в окне.

```
cargo xtask sound-smoke
```

безголово проверяет, что синтезатор выдаёт прямоугольную волну заданной частоты (частота — по
фронтам в заполненном буфере), пауза звучит тишиной, мелодия заставки приходит из вшитых данных
через мост, а узел пищалки заполняет буфер генератора; мелодию и бипы он пишет в
`.tools/out/pc_speaker.wav` — как они звучат, решает человек на слух.

### Сквозная жизнь

```
cargo xtask e2e
```

проживает инструментом `godot/tools/e2e_life.gd` полную жизнь на настоящих ядре, мосте, роутере и
экранах: заставка → новая ironman-жизнь студента с сидом 7 → шестьдесят дней на рынке с покупками
и продажами, события — первым доступным выбором → поездка → выход в главное меню (ironman
сохраняется сам) и «Продолжить» из его слота с тем же снимком ядра → ещё месяц → уход на покой →
итоги: заметка, слот ironman стёрт, метапрогрессия записана, жизнь — в «Рейтинге Форбс». После
каждого шага сверяются буфер экрана и снимок ядра. Подменён только каталог игрока —
`user://e2e`; клавиатурные помощники у него с `ui-flow-smoke` общие (`godot/tools/flow_driver.gd`).

### Предел безголовой проверки

Безголовый Godot не рендерит пиксели, поэтому машинная сверка идёт по буферу символов и цветов,
а не по картинке. Как выглядят глифы, пропорции и цвета, проверяет человек по PNG:

```
cargo xtask screenshot <экран>
```

запускает Godot в окне и сохраняет `.tools/out/<экран>.png`: экран макета — на его фикстуре,
экран без макета — на том же снимке ядра, что у `screen-smoke`; с `--crt` поверх включён
CRT-эффект, и снимок ложится в `.tools/out/<экран>.crt.png`. В CI на Linux снимок делается под
Xvfb и прикладывается к прогону как артефакт.

Сквозная жизнь доказывает, что модули собраны вместе и игра проходится от заставки до итогов, но
пиксели, звук и окно безголово не проверить. Поэтому граница проекта — точка приёмки человеком:
PNG экранов (`screenshot`), звук пищалки (`.tools/out/pc_speaker.wav` из `sound-smoke`) и запуск
экспорта своей платформы (`export`).

## Релиз

Игра выходит под три платформы (§2, §14.4): Windows x86_64, Linux x86_64 и macOS universal
(arm64 + x86_64). Пресеты экспорта — `godot/export_presets.cfg`, по одному на платформу; Windows и
Linux вшивают pck в исполняемый файл, рядом с ним лежит библиотека моста, macOS — бандл с ad-hoc
подписью. Инструменты разработки `godot/tools/` в игру не попадают.

```
cargo xtask godot-fetch --templates
```

ставит рядом с пином Godot настольные шаблоны экспорта из архива, закреплённого в `tools.toml`
(sha256 сверяется до распаковки). Пин работает в self-contained режиме: маркер `_sc_` лежит рядом с
бинарником, и данные редактора, в том числе шаблоны, живут в `.tools/godot/<версия>/editor_data/`,
а не в каталоге пользователя.

```
cargo xtask export <windows-x86_64|linux-x86_64|macos-universal>
```

собирает релизный мост (на macOS — universal), экспортирует игру в `.tools/dist/<платформа>/` и
упаковывает её в `.tools/dist/Speculant-<версия>-<платформа>.zip`. Платформа экспортируется только
на своей системе: мост — родная библиотека.

```
cargo xtask export-check
```

проверяет, что пресетов ровно три и у каждого своя платформа и архитектура, экспортирует хост и
запускает игру `--headless --quit` с логом в `.tools/dist/<платформа>.check.log`: мост грузится,
заставка открывает лобби, ошибок нет.

```
cargo xtask version-check
```

сверяет версию: она одна — `[workspace.package] version` в `Cargo.toml`; `godot/project.godot`
повторяет её в `application/config/version`, пресеты её не переопределяют, а тег релиза на коммите —
`v<версия>`. Новая версия — это правка обоих файлов и тег `v<версия>`: по нему
`.github/workflows/release.yml` сверяет версию, на родных раннерах гонит `export-check` и `export` и
прикладывает три архива к релизу GitHub.
