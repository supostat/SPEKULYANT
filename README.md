# Спекулянтъ

Торговый рогалик по мотивам DOS-игры «Коммерсантъ». Одна жизнь человека с 1984 по 2004 год: от
фарцовки при застое через кооперативы, челноков и «дикий рынок» к сетевой рознице начала 2000-х.
После 2004 года жизнь продолжается песочницей без исторических событий.

Игра нарочно выглядит как программа для DOS: текстовый режим VGA 80×25, шрифт IBM VGA с
кириллицей, рамки псевдографикой, пищалка PC-speaker и по желанию эффект ЭЛТ-монитора.

- **Платформы:** Windows x86_64, Linux x86_64, macOS (universal).
- **Язык игры:** только русский.
- **Движок:** Godot 4.7, логика — ядро на Rust через godot-rust, интерфейс — GDScript.

## Об игре

- **Время идёт само.** День проходит за секунды, на рынке, в дороге и в зоне время не ждёт;
  событие останавливает его и требует решения. Пробел — пауза, «+» и «−» — скорость.
- **Деньги — на разнице цен между городами.** 40 товаров со своей историей цены по годам и 10
  городов от Москвы до Пекина: Варшава открывается в 1990-м, Стамбул — в 1991-м, Пекин — в 1992-м,
  а в Берлин до 1990 года едут только по блату. Крупная сделка сдвигает цену, гиперинфляция бьёт по
  тем, кто держит рубли.
- **Эпоха меняет правила.** Что вчера было статьёй, завтра становится профессией: больше 370
  событий, указы, кризисы, деноминация, соперники, которые торгуют по тем же правилам.
- **Своё дело.** Ларьки, магазин, цех варёнок, челночные рейсы, банк — через управляющих с
  политиками.
- **Зона — отдельный режим** со своей экономикой сигарет и чая.
- **Жизнь конечна.** Смерть, срок или разорение кончают жизнь; следующая начинается с нуля, но со
  знаниями прошлых: записной книжкой цен, слухами о будущем и открытыми биографиями. Режимы —
  ironman (одно сохранение, само) и свободный (именованные слоты), рекорды у каждого свои.

Полное описание замысла — [docs/SPEKULYANT.md](docs/SPEKULYANT.md), живые макеты экранов —
[design/design-book.html](design/design-book.html).

## Управление

| Клавиша | Что делает |
|---|---|
| F1 | помощь |
| F2–F7 | действия экрана — подписи в нижней строке; на рынке: купить, продать, ехать, связи, дела, пейджер |
| F10, Esc | назад; на рынке и в зоне — меню выхода |
| ↑ ↓ | выбрать строку |
| ◄ ► | сменить вариант; на графике цены — цены товара по городам |
| Enter | подтвердить, ехать; на рынке — график цены товара |
| Цифры | выбор в событии, количество, сумма, сид |
| Пробел | пауза |
| + − | быстрее, медленнее |
| F11, Alt+Enter | полный экран или окно |

Мышью можно щёлкать по строкам и по F-клавишам. Окно открывается с наибольшим целым увеличением,
которое влезает в экран, чтобы буквы оставались чёткими.

## Сохранения и настройки

Игра хранит всё в каталоге пользователя Godot:

| Система | Каталог |
|---|---|
| Windows | `%APPDATA%\Godot\app_userdata\Спекулянтъ\` |
| macOS | `~/Library/Application Support/Godot/app_userdata/Спекулянтъ/` |
| Linux | `~/.local/share/godot/app_userdata/Спекулянтъ/` |

Там лежат `saves/<слот>.spk` — жизни, `meta.spk` — знания прошлых жизней и рекорды, `settings.cfg` —
настройки. Файл жизни привязан к данным игры: сборка с другим каталогом `data/` его не прочтёт.

## Сборка из исходников

Нужны Git и Rust через [rustup](https://rustup.rs): точная версия тулчейна подтянется сама из
`rust-toolchain.toml`. На Windows ещё нужны Visual Studio Build Tools с компонентом «Разработка
классических приложений на C++». Godot ставить не нужно — проект скачивает свою версию сам и
сверяет её контрольную сумму.

```
cargo xtask godot-fetch
cargo xtask build-godot
```

Первая команда кладёт Godot 4.7.2 в `.tools/godot/4.7.2-stable/`, вторая собирает мост — библиотеку
с ядром игры — в `godot/bin/`. Запуск игры из исходников:

| Система | Команда |
|---|---|
| macOS | `.tools/godot/4.7.2-stable/Godot.app/Contents/MacOS/Godot --path godot` |
| Linux | `.tools/godot/4.7.2-stable/Godot_v4.7.2-stable_linux.x86_64 --path godot` |
| Windows | `.tools\godot\4.7.2-stable\Godot_v4.7.2-stable_win64_console.exe --path godot` |

С флагом `-e` та же команда открывает проект в редакторе Godot. После правки Rust-кода мост
пересобирается той же `cargo xtask build-godot`.

### Готовая сборка игры

Каждая платформа собирается на своей системе:

```
cargo xtask godot-fetch --templates
cargo xtask export-check
cargo xtask export windows-x86_64
```

Вместо `windows-x86_64` — `linux-x86_64` или `macos-universal`. Архив ложится в
`.tools/dist/Speculant-<версия>-<платформа>.zip`.

Без нужной системы под рукой все три архива собирает GitHub Actions:

- **по тегу `v<версия>`** сценарий [release.yml](.github/workflows/release.yml) сверяет версию,
  собирает Windows, Linux и macOS и прикладывает архивы к релизу;
- **ручной запуск** (Actions → release → Run workflow) собирает те же архивы как артефакты
  прогона, без релиза.

Версия игры одна — `[workspace.package] version` в `Cargo.toml`; `godot/project.godot` повторяет её,
а `cargo xtask version-check` следит, чтобы они и тег совпадали.

## Устройство проекта

```
crates/
  speculant-core/      вся игровая логика: экономика, время, события, дела, зона, сохранения
  speculant-godot/     мост в Godot — класс SpeculantGame
  speculant-sim/       симулятор баланса: боты проживают тысячи жизней на настоящем ядре
  speculant-validate/  проверка данных игры
  xtask/               единый раннер сборки и проверок: cargo xtask <команда>
data/                  контент игры в TOML: товары, города, события, биографии, люди
godot/                 интерфейс на GDScript: экраны, ввод, звук, ЭЛТ-эффект
design/                дизайн-книга и эталоны экранов
docs/                  замысел, руководство автора контента, план разработки
```

Ядро не знает о Godot — за этим следит `cargo xtask deps-check`. Интерфейс только показывает
снимок мира от ядра и передаёт ему команды. Мост для этого держит четыре метода: `new_life`,
`advance`, `apply` и `view_json`; снимок и команды ходят в JSON.

Интерфейс пишется кодом: в проекте одна сцена `godot/main.tscn` с одной нодой, каждый экран — скрипт
в `godot/src/screens/`, который рисует текстовый экран 80×25 и отвечает на ввод намерением.

## Контент

Контент — файлы TOML в `data/`, один файл на сущность, имя файла — идентификатор. Формат каждой
сущности, правила событий и примеры — в [docs/CONTENT.md](docs/CONTENT.md).

```
cargo run -p speculant-validate -- data --strict
cargo xtask new-event perestroika cooperative_raid
cargo xtask coverage-check
```

Первая команда проверяет все данные и называет каждую ошибку с файлом и строкой (`--watch` —
проверять при каждом сохранении). Вторая создаёт заготовку события. Третья прогоняет ботами
столько жизней, сколько задано в `data/balance.toml`, и проверяет, что каждое событие хоть раз
случается. Пороги объёма, баланса и покрытия лежат только в этом файле. Строки игры пишутся только символами шрифта —
это проверяет `cargo xtask charset-check`.

## Проверки

```
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo xtask balance-check all
cargo xtask e2e
```

Тесты ядра и инструментов, линтер, баланс жизней по эпохам и сквозная жизнь в настоящем Godot —
от заставки через торговлю, события и поездку до итогов. Весь набор, который гоняет CI, — в
[ci.yml](.github/workflows/ci.yml); полный список команд показывает `cargo xtask` без аргументов.
